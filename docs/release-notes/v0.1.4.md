# TM Publisher 0.1.4

[English](#english) · [Türkçe](#türkçe)

## English

Better logs and a way to report a problem. Nothing about your data changes; update as in the README (**Update**): quit the
scheduler from its tray (Windows) or from Settings → Background scheduler, replace the files, start the window.

### What changed since 0.1.3

- **Log files** are now one file per day and program in the data folder's `logs/`: `app-yyyy-MM-dd.log` (window),
  `scheduler-…` (background scheduler), `notify-…` (notifications). Each start and each new file begins with one line naming
  the program, version and commit, operating system, architecture and .NET version.
- **Only the last 7 days are kept** (today included). Older files are deleted when a program starts and when the day changes
  while it runs, by the date in the file name; the 0.1.0–0.1.3 files (`tmpublisher-…`) are cleaned the same way; other files in
  the folder are left alone. A file stops growing for the day at 20 MB (one warning line says so).
- **Information and above** are written (no debug lines). Starts and ends, what you do and its result, each post and each
  target with how long it took, the next scheduled post when it changes and a sign of life at most once an hour, and one line
  per platform request (method, platform host, path with ids and tokens as `*`, HTTP status, duration; never the query, the
  headers or a body). Retries and fallbacks are warnings, and so is a platform that does not answer within the time-out (your own
  Stop is an information line); failed operations are errors, and unhandled exceptions, a database missing next to its key and a
  failing key protection are critical.
- **Masked before writing:** your home folder becomes `~`, e-mail addresses `***@***`, tokens (Bearer / Basic, secret query and
  JSON values, webhook and bot addresses, API key shapes, JWTs) `***`. Blocked posts are logged with a reason but without
  account names; a Mastodon or Bluesky server name is written as "(account server)", also inside error messages. If two copies
  of one program write at the same moment (a second start of the window), their lines do not overwrite each other; a log file
  that cannot be opened is tried again a minute later.
- **Report a problem** (bottom of the side menu). Nothing is sent automatically. **Prepare logs** makes
  `tm-publisher-logs-<date>-<time>.zip` in the data folder's `reports/` (the last 7 days of 0.1.4 logs, masked again, and
  `system.txt`: version, OS, architecture, .NET, interface language, drawing mode, which helper programs are there) and shows
  it; the newest 5 zips are kept. The 0.1.0–0.1.3 log files never go into the zip (they could name an account). A zip that
  could not be finished is removed, so there is no broken one to attach. **Report on GitHub** opens the bug form with the version and system filled in; drag the zip
  into it. **Copy details** copies `system.txt`.
- Saving the default tags no longer fails silently on a database error: it shows the error and logs it.
- Release scripts: the output folder can be chosen (`-Out`, `TMPUBLISHER_OUT`), and the Windows script builds the linux-x64
  scheduler again (an argument was passed letter by letter).

### Measured

Release files of 0.1.3 and 0.1.4 one after the other, each program alone with its own empty data folder, left alone for 90
seconds; CPU over the last 60 of them (the last run of each row with the files of this release's final commit). Windows 11: Task Manager's **Memory** column (private working set) / working set /
private, MiB.

| | 0.1.3 | 0.1.4 |
|---|---|---|
| Windows: scheduler waiting (4 runs) | 5.5 / 20.1–20.9 / 7.3–7.4, CPU 0 ms | 5.6 / 20.3–21.1 / 7.2–7.4, CPU 0–16 ms |
| Windows: window, first-start page (3 runs) | 24.8–25.5 / 77.7–81.2 / 27.5–28.2, CPU 0–31 ms | 25.3–25.4 / 82.3–83.3 / 28.1–28.4, CPU 0–31 ms |
| Raspberry Pi 5 (arm64): scheduler waiting, RSS / PSS / private (4 runs) | 18.4–19.0 / 13.1–13.8 / 12.9–13.5, 0 CPU ticks | 18.7–19.3 / 13.4–14.0 / 13.2–13.8, 0 CPU ticks |

The scheduler's log stays small while it waits: about 1 KB after start (the header, a few start lines and the memory line
a minute later), then one line when the next post changes and at most one line an hour.

### Known limits

Unchanged from 0.1.3 (linux-x64 scheduler is not native code, master password after each start, no tray icon on Linux, the
three files of the Windows zip stay together, the platform limits). The logs zip is made only when you press the button and
only you attach it; please look into it before you share it.

## Türkçe

Daha iyi günlükler ve hata bildirme yolu. Verilerinizde bir şey değişmez; README'deki gibi güncelleyin (**Güncelleme**):
zamanlayıcıyı tepsisinden (Windows) ya da Ayarlar → Arka plan zamanlayıcısı'ndan kapatın, dosyaları değiştirin, pencereyi açın.

### 0.1.3'ten bu yana değişenler

- **Günlük dosyaları** artık veri klasörünün `logs/` klasöründe gün ve program başına bir dosya: `app-yyyy-MM-dd.log` (pencere),
  `scheduler-…` (arka plan zamanlayıcısı), `notify-…` (bildirimler). Her açılış ve her yeni dosya; programı, sürümü ve commit'i,
  işletim sistemini, mimariyi ve .NET sürümünü yazan bir satırla başlar.
- **Yalnız son 7 gün tutulur** (bugün dahil). Daha eskiler program açılırken ve çalışırken gün değişince, dosya adındaki tarihe
  göre silinir; 0.1.0–0.1.3 dosyaları (`tmpublisher-…`) da aynı şekilde temizlenir; klasördeki başka dosyalara dokunulmaz. Bir
  dosya o gün 20 MB'a ulaşınca büyümeyi bırakır (bir uyarı satırı bunu yazar).
- **Information ve üstü** yazılır (debug satırı yok). Açılış ve kapanış, yaptığınız işlemler ve sonucu, her gönderi ve her hedef
  ile süresi, sıradaki planlı gönderi değişince ve en çok saatte bir "çalışıyorum" satırı, her platform isteği için bir satır
  (yöntem, platform adresi, kimlik ve anahtarları `*` olan yol, HTTP durumu, süre; sorgu, başlıklar ve gövde asla). Yeniden
  denemeler ve yedek yollar uyarı, süresi içinde cevap vermeyen platform da uyarı (sizin Durdur'unuz bilgi satırı); başarısız
  işlemler hata; yakalanmayan istisnalar, anahtarının yanında olmayan veritabanı ve çalışmayan anahtar koruması kritik.
- **Yazmadan önce gizlenir:** ev klasörünüz `~`, e-posta adresleri `***@***`, anahtarlar (Bearer / Basic, gizli sorgu ve JSON
  değerleri, webhook ve bot adresleri, API anahtarı biçimleri, JWT'ler) `***` olur. Engellenen gönderiler sebebiyle ama hesap adı
  olmadan yazılır; Mastodon ya da Bluesky sunucu adı hata iletilerinin içinde de "(account server)" olarak geçer. Aynı programın
  iki kopyası aynı anda yazarsa (pencerenin ikinci açılışı) satırları birbirinin üstüne yazılmaz; açılamayan günlük dosyası bir
  dakika sonra yeniden denenir.
- **Hata bildir** (yan menünün altında). Hiçbir şey kendiliğinden gönderilmez. **Günlükleri hazırla**, veri klasörünün
  `reports/` klasöründe `tm-publisher-logs-<tarih>-<saat>.zip` dosyasını yapar (son 7 günün 0.1.4 günlükleri, yeniden gizlenmiş, ve
  `system.txt`: sürüm, işletim sistemi, mimari, .NET, arayüz dili, çizim kipi, hangi yardımcı programların olduğu) ve gösterir;
  en yeni 5 zip tutulur. 0.1.0–0.1.3 günlük dosyaları zip'e hiç girmez (hesap adı geçebilir). Bitirilemeyen zip silinir; eklenecek
  bozuk zip kalmaz. **GitHub'da bildir**, hata formunu sürüm ve sistem bilgisi dolu olarak açar; zip'i forma sürükleyin.
  **Bilgileri kopyala**, `system.txt`'yi panoya kopyalar.
- Varsayılan etiketleri kaydetmek veritabanı hatasında artık sessizce düşmüyor: hatayı gösterip günlüğe yazıyor.
- Sürüm betikleri: çıktı klasörü seçilebiliyor (`-Out`, `TMPUBLISHER_OUT`) ve Windows betiği linux-x64 zamanlayıcısını yeniden
  derleyebiliyor (bir argüman harf harf geçiyordu).
